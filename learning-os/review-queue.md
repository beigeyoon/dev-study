## 곧 due
**2026-08-03 — 인메모리 vs 관계형 DB (imp 4, m3):**
- 🎯 **최우선 관문 = 1차 원리 (3번째 시도).** *"속도는 성질이 아니라 거래다 / 진짜 질문은 **이 데이터는 무엇을 팔아도 되는가**"* 를 **표·빈칸 사다리 없이** 꺼내는지. 2세션 연속 유도로만 도달 — 이번에도 못 꺼내면 **암묵적 사용 ↔ 명시적 언어화의 간극**을 별도 결함으로 승격하고 다른 접근(먼저 말하게 하고 상황을 붙이기)으로 전환.
- 🎯 **인덱스(7-31 신규 결함):** *"인덱싱이 되어 있어서"* 동어반복 금지. ① **왜 이기나** = 접근 횟수(500만 vs 20, 1,000배 유리한 하드웨어를 250,000배 횟수가 뒤집음) ② **뭘 팔았나** = 공간 + 쓰기 속도(인덱스 표가 디스크에 하나 더 / 이사 가면 정렬 재유지). 둘 다 무힌트로.
- 🎯 **청구서 ③ 자력 발화:** 7-31엔 배치 이유를 ①②로만 댔다. 조회 능력 상실을 **먼저** 꺼내는지 + *"비용이 크다"* 가 아니라 **"필터링 부담이 저장소→애플리케이션으로 옮겨간다"** 로 말하는지.
- 유지 확인(이미 통과): 배치 4종 / 청구서 귀속(무효화는 사본 있을 때만) / RAM 자격 2조건 / 캐시 패턴 / stale = "자신 있는 오답".
