## 진행한 것
### 🔴 Promise.all 회귀 재점검 (단독 Feynman) — ✅ 완전 회복, m3→4
6-24에 무너졌던 개념. 오늘은 전부 **무힌트 자력 재구성**:
- **버전1(순차 await) 타이밍:** "fetchB는 t=1에 호출, 첫 줄 await 이후는 전부 대기" — 6-24에 *"fetchB도 이미 시작됐다"*고 오답했던 바로 그 지점을 스스로 정정. **회귀 회복 확인.**
- **버전3(분리 호출 후 await 3개, `Promise.all` 미사용) = 1초** 자력 도출 → "병렬성은 `Promise.all`이 아니라 *출발 시점(in-flight)*에서 나온다, all은 편한 집계기일 뿐"을 **스스로 증명**.
- **CPU 경계(`new Promise` 안 while로 1초 태움) = 3초**를 "while은 Web API에 못 넘기고 JS 스레드가 직접 실행"으로 정확히 도출 → 1차 원리 **"겹침은 실행이 아니라 기다림에서"** 확립.
- **사용자 자력 심화 질문:** "배열 `[heavyA(),heavyB(),heavyC()]`에서 heavyB의 `Date.now()`는 heavyA의 while+resolve가 다 끝난 뒤에야 평가되나?" → 맞음. 함수 호출은 몸통을 끝까지 동기 실행 후 리턴, `await`(양보점) 없으면 인터리빙 0 → 완전 직렬. (executor 동기 실행 이해 심화 — Promise 페이지와 접합.)

## 막힌 지점 / 보강한 것
- **전이(Web Worker)에서 막힘:** "한 스레드론 CPU 못 겹침"은 자력 도출했으나 탈출구 **이름**을 못 꺼냄("스레드 하나 더 = 프로세스 하나 더?"로 오답).
- **오개념 교정:** 스레드를 더 얻는 데 새 프로세스는 필요 없음 — **한 프로세스가 스레드 여럿**(process-vs-thread 그대로). Web Worker = 브라우저가 JS에 주는 추가 스레드, `postMessage`로 복사(race 회피).
- **봉인 한 문장:** "`Promise.all`은 **기다림**을 겹치고(스레드 그대로), Web Worker는 **일**을 겹친다(스레드 추가=진짜 병렬)." → 다음 복습에서 이 전이를 무힌트로 꺼내면 m5.
