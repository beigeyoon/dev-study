### ✅ 클로저 — m3→4 복귀 (makeCounter 무힌트 통과)
- 1일 리셋(7-22 회귀) 뒤 `makeCounter` 앵커를 **무힌트로**: 출력 `1 2 1` + "a·b는 다른 호출→배낭 따로" + "힙에 살고 참조 하나라도 남으면 산다"(수명=도달 가능성)까지 자력. 7-22의 `1 2 3`/공유 오답 완전 회복.
- **정밀화:** 답을 "**함수마다** 배낭 따로"로 *표현*하는 잔여 오개념을 반례로 사냥 — `한 호출 → {inc, get}`이 `count` 공유(`c.get()===2`). 사용자가 "함수마다면 inc/get이 갈려야 하는데 안 갈린다"는 모순을 **스스로 잡음** → **배낭 = 함수 아닌 호출(스코프) 소유** 봉인.
- → m4 복귀, review_due 7-31(리셋 후 첫 통과=계단 복귀).

### ⚠️ HTTP — m3 유지 (DELETE 앵커, Host 존재 이유 회귀→유도 회복)
- ✅ **durable(무힌트):** 요청 3층 / status `404`·4xx=클라이언트·5xx=서버(책임 소재) / fetch가 404에도 **resolve**→status code로 판별. ~30일 공백에도 코어 버팀.
- ⚠️ **회귀:** `Host` 헤더 *존재 이유*. "**IP 하나=사이트 하나**" 오개념을 들고 있어 "도메인이 시작줄에 없어 생기는 문제"를 못 봄(6-23엔 1차 원리로 자력 도출했던 것).
- 🔧 **정정:** DNS 여러 도메인→같은 IP = 버추얼 호스팅 → 한 IP에 `api/blog/shop` 세 듦 → 첫 줄 `/users/42`만으론 "누구네?" 모호 → 그 칸이 `Host:`.
- 💡 **새 질문 해소(설계 의도):** "왜 첫 줄 아닌 헤더에?" → **하위 호환.** 배포된 첫 줄 형식은 못 바꾸고, 헤더는 "못 알아들으면 무시" 가능한 열린 확장 슬롯 → 새 `Host` 헤더로 끼움(1.1 필수화, 2.0은 `:authority`).
- → m3 유지, review_due 30→14일 당김(8-07).

## 막힌 지점 / 보강한 것
- **클로저:** "배낭 소유 주체" 표현이 함수↔호출로 흔들림 → 반례(inc/get)로 굳힘.
- **HTTP:** "한 IP = 한 사이트"라는 **진짜 오개념** 정정(버추얼 호스팅). Host가 헤더인 이유(하위 호환·확장 슬롯) 신규 습득 → **mindset 전이:** 배포된 포맷 코어는 불변, 확장은 optional 슬롯으로.
