# 진행한 것 — 인메모리(Redis) vs 관계형 DB(MySQL) 첫 학습 (신규 · learning · m2)

**앵커:** *"RAM이 디스크보다 1,000배 빠른데, **왜 모든 데이터를 Redis에 안 넣나?**"* → 청구서를 스스로 사냥하게 함.

| 단계 | 결과 |
|---|---|
| 청구서 ① 용량·비용 | ⭕ **자력** — "빠른 만큼 비싸지 않을까, 커버리지도 적을 듯" |
| ↳ 조임 | 🔧 "비싸다"와 "적게 담긴다"는 별개 청구서가 아니라 **같은 축의 원인·결과**임을 코치가 교정 |
| 청구서 ② 휘발성 | 🔺 상황 제시(전원 뽑힌 노트북) 후 **용어 자력 회수** |
| ↳ "그럼 왜 세션은 Redis에?" | ⭕ **자력** — "세션은 기한이 유한하니까, 영원히 보관할 필요 없음" (**수명 축**) |
| ↳ 코치 추가 | 🔧 두 번째 성질 = **잃어도 재생성 가능**(재로그인). 주문 내역은 세상에 사본이 없다 |
| 청구서 ③ 조회 능력 | ⭕ **자력** — "엑셀로 익스포트해서 검색? DB처럼 WHERE로는 못 하지" = **full scan을 이름 없이 재발명** |
| 역전 앵커(느린 디스크가 이김) | ⭕ 책 색인 비유 제시에 *"인덱싱, 목차"* **즉답** |
| 실무의 답 ① 배치 | ⭕ **자력** — "세션은 Redis, 고객 정보는 MySQL" |
| 실무의 답 ② 캐시 | ⭕ **자력 도출** — *"인기 상품 몇 개만 Redis에 복제해두기"* (= cache-aside를 이름 없이 설계) |
| 캐시의 대가(stale) | 🔺 흐름 추적 힌트 2단계 후 *"아 수정된 값이 캐시에는 업데이트가 안 된다고?"* |
| 🎯 1차 원리 | ❌ **미도달** (아래 참조) |

## 봉인된 문장들
- **RAM에 앉을 자격 = 자주 읽히고 + 잃어도 재생성 가능한 데이터.** (세션·캐시가 정확히 이 조건)
- **하드웨어가 1,000배 빨라도 접근 횟수가 250,000배 차이 나면 느린 하드웨어가 이긴다 → 자료구조가 하드웨어를 이긴다.**
- **세션 소실 = 정직한 실패("모르겠다") / 캐시 stale = 자신 있는 오답.** 캐시의 진짜 대가는 "가끔 틀린다"가 아니라 **"틀린 걸 아무도 모른다."**

# 막힌 지점 / 🔴 다음 관문 2건

### 1. 1차 원리에 못 올라감
사용자가 든 건 **결론**("그래서 Redis만 쓰면 안 된다")이었고, 그 위 층은 못 꺼냄:
> **속도는 성질이 아니라 거래다.** Redis는 그냥 빠른 게 아니라 **용량·영속성·조회 능력을 팔아서** 속도를 샀다. 그러니 "뭐가 더 좋은가"는 성립하지 않는 질문이고, 진짜 질문은 **"이 데이터는 무엇을 팔아도 되는가"**.

7-27의 *"상태는 제거되지 않고 이동할 뿐이다"* 와 같은 높이. 그때는 **위치**를, 여기선 **위치마다 무엇을 팔았는지**를 본다. → **7-30 복습의 m3 기준.**

### 2. 🆕 청구서 귀속 오류 (신규 결함 — 관찰 승격)
마무리 답변에서 *"다 Redis에 넣기"* 의 죄에 **캐시 무효화**를 붙였다. 그런데:

| 선택 | 원본 | 무효화 문제 |
|---|---|---|
| A. 다 Redis에 넣기 | Redis뿐 | **없음** — 사본이 없으니 어긋날 상대가 없다 |
| B. MySQL + Redis 캐시 | MySQL | **있음** |

A의 죄는 **용량·비용 / 휘발성 / 조회 능력** 3장뿐. 무효화는 **B를 골랐을 때 붙는 값**이다.
→ **트레이드오프를 발생시킨 선택에 정확히 귀속시키는 능력**에 빈틈. **7-27의 "양 날 비대칭 진동"과 같은 결의 결함**(트레이드오프를 절반만 들거나 엉뚱한 곳에 붙임)일 수 있음 — 두 페이지에 걸쳐 관찰 대상으로 등록.
