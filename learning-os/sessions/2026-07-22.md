## 진행한 것
### ✅ 통합 앵커 (frontend 비동기 6개) — 통과, 공백에도 버팀
출력 순서 앵커(`console.log` + `setTimeout` + `.then` + `await Promise.resolve()`) → **`1 4 6 3 5 2` 즉답.** ①왜 `1 4 6`이 뭉텅이 먼저(콜스택 sync-to-empty) ③왜 `2` 꼴찌(매크로) 정확. ②`3<5`는 처음 "resolve 시점이 다르다"로 흐렸으나 → **핵심 정밀화 유도:** 둘 다 이미 resolved라 *같은 동기 구간*에 큐잉, 순서를 가른 건 **스케줄링하는 동기 줄의 실행 순서**(`.then` 줄이 `await` 줄보다 먼저). **`await P` = "함수의 나머지"를 `P.then(나머지)`로 감싸는 문법 설탕** 확립.
- **확인 트위치:** `.then(→3)`을 `foo()` 아래로 이동 → **`1 4 6 5 3 2` + "동기 줄 순서가 바뀌어서" 무힌트 정답.** await=.then 이해가 응용까지 굳음 → **async/await m3→4.**

### ✅ 🔴 Promise.all 단독 Feynman — 회귀 완전 회복 + 전이 자력 → m4→5
- A=3초 / B=C=1초, **B=C 이유**(배열도 원소를 왼쪽부터 동기 호출 → await 전 셋 다 in-flight, all은 집계기) 자력.
- ⚠️ "C는 병렬성" 오개념 노출 → **스스로 교정:** 스레드 B·C 모두 1개, 겹치는 건 실행 아닌 **기다림**, 1초 세는 건 **브라우저 Web API** → 둘 다 **동시성**, 병렬성 아님.
- CPU 경계(heavy×3)=3초 자력. **전이 "스레드 여러 개 필요"를 무힌트 도출** — 7-01 "프로세스 하나 더?" 오답을 **스레드**로 자가 교정. `Web Worker` **이름만** 힌트(§2 reference성).
- **봉인:** "Promise.all은 *기다림*을 겹친다(스레드 1개) / Web Worker는 *일*을 겹친다(스레드 추가=진짜 병렬)." → **status mastered.**
