## 진행한 것

### 1유닛 — 인메모리(Redis) vs 관계형 DB (m2 → 3, understood 승격, feynman 통과)
앵커: 처음 보는 배치 문제. 데이터 4종(로그인 세션 / 주문 내역 / 회원 프로필 / 실시간 인기 검색어)에 CTO의 *"RAM이 1,000배 빠르니 전부 Redis에 넣자"* 를 반박.

- **배치 4/4 무힌트.** 세션·검색어 → Redis, 주문·프로필 → MySQL. 기준으로 *"날아가도 다시 생성 가능한 데이터에 한해서"* 를 **맨 앞에 세움** — 7-29에 자력으로 잡은 축이 5일 뒤에도 살아 있음.
- 🎯 **7-29 결함(청구서 오배치) 회복 확인.** "500만 명을 MySQL 원본 + Redis 사본으로 두면?" 반례에 **무효화**를 정확히 붙임. 사본이 존재하는 구도에서만 무효화가 생긴다는 걸 제대로 사용.
- 청구서 ③(조회 능력 상실)은 **힌트 1단계**(마케팅팀의 "지난달 가입 + 서울 거주" 쿼리) 뒤 회수 — *"where로 select 하는 기능이 없음"*.
- 인덱스의 청구서(공간 · 쓰기 속도)를 새로 깔아 보강. "왜 이기나"는 곱셈으로: 하드웨어 1,000배 유리 vs 접근 횟수 250,000배 불리 → **자료구조가 하드웨어를 이긴다.**
- **1차 원리 도달(유도).** "얻은 것 / 판 것" 4줄 표 + 빈칸 문장 사다리를 깔자 두 문장을 정확히 완성. *"뭐가 더 좋은가는 성립 안 하는 질문"* 까지는 자력.

### 2유닛 — 클로저 (m4 유지)
앵커: `makeCounters()` → `{ inc, get }`, `a`/`b` 두 호출, `a.inc(); a.inc(); b.inc();` → **`2 1`**.

- **①②③ 3연속 무힌트.** `a`·`b`는 다른 배낭 / 한 호출 안의 `inc`·`get`은 같은 배낭 공유 / `count`는 **힙**에 있고 *"아직 참조하는 곳이 남아있기 때문에"* 안 죽음. **7-22 회귀 완전 봉인, 3세션 연속 통과.**
- 표현 정밀화: `a`는 함수가 아니라 반환된 객체 → 정확한 규칙은 **배낭을 만드는 건 함수의 *정의*가 아니라 *호출***.
- 🎁 **오늘의 수확 — 렌즈가 층을 건넘.** 1유닛에서 세운 *"공짜로 얻은 줄은 없다"* 를 클로저에 댐:
  > **클로저 = 상태 유지·캡슐화를 사려고 "메모리의 자동 회수"를 판 거래.**
  > 스택 변수는 함수가 끝나면 공짜로·확실하게 사라진다. 클로저는 그걸 힙으로 대피시켜 살리는 대신 *언제 사라지는지 확신할 수 있음*을 판다. 청구 순간 = **메모리 누수**(React `useEffect` cleanup 누락 버그의 정체).

## 막힌 지점 / 보강한 것

🔴 **두 개념에서 같은 패턴이 동시에 관측됨 — "암묵적 사용 ↔ 명시적 언어화"의 간극.**

| | 알고 쓰는가 | 말로 꺼내는가 |
|---|---|---|
| DB 1차 원리 | ✅ 세션 첫 답변에서 *"재생성 가능한 데이터에 한해서"* 라며 **이미 그 질문을 쓰고 있었음** | ❌ 표 + 빈칸 사다리를 깔아줘야 나옴 (**2세션 연속 실패**) |
| 클로저 트레이드오프 | ✅ 힙·수명·참조를 완벽히 설명 | ❌ 표를 깔아줘야 "판 것 = 힙 메모리"가 나옴 |

**원리를 모르는 게 아니라, 쓰던 것을 이름 붙여 한 층 위로 올리지 못한다.** m4→5의 병목이 여기일 가능성 → gaps.md에 최우선 결함으로 등록.

🔴 **동어반복 패턴(신규).** *"MySQL이 왜 이기나"* → *"인덱싱이 되어 있어서"*. 이름을 답으로 착각. 5일 전 "책 색인" 즉답이 **구조 이해로 굳지 않았다**는 증거 — **비유 즉답 ≠ 이해.**

🔵 청구서 ③이 자력으로 안 나옴 + *"검색비용이 큼"* 이라는 무른 표현 → **"비용이 커진 게 아니라 필터링 부담이 저장소 → 애플리케이션으로 옮겨간 것"** 으로 정밀화.
