# 학습 카드 발행 시스템 — 설계 문서

- **작성일**: 2026-07-22
- **상태**: 승인됨 (구현 계획 대기)
- **목적**: 위키에 쌓인 잘 학습된 개념을, 다른 사람도 공부할 수 있는 **질문 형태의 카드 이미지**로 만들어 **스레드(Threads)** 에 발행한다. 발행은 학습의 *부산물*이어야 하며(저마찰), 별도의 직업이 되어선 안 된다.

---

## 1. 핵심 컨셉과 결정 로그

브레인스토밍에서 확정한 결정들. 각 항목은 "왜"까지 박아둔다(나중에 흔들리지 않도록).

| # | 결정 | 이유 |
|---|------|------|
| 콘텐츠 | **파인만 앵커(추론 문제)** 가 주력 카드 | `내 파인만 설명`의 앵커("`makeCounter()` 출력은?")는 정의 암기가 아니라 *추론을 유도* → 다른 스터디 카드와의 차별점. 이 위키만의 자산. |
| 구조 | **질문 → 해설**, 단 질문 간결·해설 카드 최소 | 앵커의 가치는 "출력이 뭐냐"가 아니라 추론 사슬. 티저 1장은 자산 낭비. 단, 페이지의 긴 서술(회귀로그 포함)을 그대로 옮기지 않고 **정수만 압축**. |
| 발행처 | **스레드(Threads)** | 정적 카드 이미지에 맞고, 단위 생산비가 낮아 학습 부산물 수준으로 유지 가능. 대화형이라 추론 문제("답 맞혀봐")와 궁합. 한국 개발 커뮤니티 활성. |
| 리빌 방식 | **B안**: 질문 카드 = 본문 첨부 이미지 / 정답 카드 = **자기 답글** 이미지 | 답을 보려면 *의식적으로 눌러야* 함 → 능동적 인출(retrieval) 강제. 위키 철학(§5 "추론시키고 막히면 힌트")과 일관. 본문이 깔끔해 도달↑, 댓글로 각자 답 유도. |
| 자동화 | **접근 1**: 큐레이션 수동 + 렌더 자동 + 발행 수동 | 노력을 "질문 압축"(가치 있는 편집)에만. 렌더는 자동. 공개 발행은 의도적으로 수동(통제·검토). |
| 매체 확장 | 콘텐츠 원자(질문 카드 + 정답 카드)는 **나중에 쇼츠로도 렌더 가능**하게 설계 | 정적 카드로 무엇이 먹히는지 싸게 검증 후, 반응 좋은 것만 영상으로 승격. 카드가 그대로 영상 프레임이 됨. (v1 범위 아님) |

### 매체 형태 (스레드)
- 스레드 포스트 1개 = **본문 텍스트**(훅 한 줄 + 해시태그) + **첨부 이미지**(질문 카드).
- **정답 카드**는 같은 스레드의 **자기 답글**에 이미지로 첨부.
- 카드는 "본문에 타이핑하는 글"이 아니라 **첨부하는 이미지 파일**.

## 2. 산출물 (3덩어리)

1. **`/card` 스킬** (`.claude/skills/card/`) — 카드 제작 워크플로우(사용자 발동).
2. **카드 소스 + 렌더 파이프라인** (`knowledge/cards/`, HTML 템플릿, `scripts/render-cards.js`, 교체형 폰트).
3. **위키 통합** (`learning-os/publish-queue.md`, `CLAUDE.md` 포인터).

---

## 3. 데이터 모델 — `knowledge/cards/`

카드 1장당 파일 하나. 개념 페이지(학습용, 길고 회귀로그 섞임)와 **분리**하고 `concept` 필드로 역링크. 기존 `gray-matter` 파서를 그대로 사용.

**파일**: `knowledge/cards/<id>.md` — 구조 = **frontmatter(메타)** + **라벨된 마크다운 섹션(내용)**.

**frontmatter (파서가 읽는 메타):**

```yaml
---
id: closure-makecounter-01
concept: concepts/closure.md    # 개념 페이지로 양방향 링크
domain: frontend
status: draft                   # draft → approved → published
accent: lime                    # 카드 강조색 (기본 lime)
created: 2026-07-22
published:                      # 발행일(수동 기록), 미발행이면 비움
tags: [closure]
---
```

**본문 (렌더러가 `##` heading으로 파싱하는 섹션):**

- `## 질문코드` — 표준 마크다운 코드블록(` ```js … ``` `). 언어 힌트로 신택스 하이라이팅 대상. (예: `makeCounter` 정의 + `a`,`b` 두 호출 + `console.log(a(), a(), b())`)
- `## 헤드라인` — `출력은? 🔥`
- `## 정답` — `1 2 1`
- `## 왜` — `a·b는 makeCounter의 다른 호출 → 각자 다른 count(배낭). a는 두 번 눌러 1→2, b는 새 count라 1.`
- `## 한줄정리` — `배낭은 **함수**가 아니라 **호출**이 갖는다` (`**굵게**` = 카드에서 네온색으로 강조할 키워드)
- `## 캡션` — `이 코드 출력, 3초 안에 맞혀봐 👇 정답은 댓글에서 #자바스크립트 #클로저`

## 4. 렌더 파이프라인 — `scripts/render-cards.js`

- **입력**: `knowledge/cards/*.md` 중 `status: approved`.
- **처리**: 각 카드 → HTML 카드 템플릿에 값 주입 → **Puppeteer(헤드리스 크롬)** 로 **1080×1350(4:5)** PNG **2장**(질문·정답) 렌더. `deviceScaleFactor: 2`로 선명하게.
- **출력**: `site/cards/dist/<id>-q.png`, `<id>-a.png`.
- **왜 Puppeteer**: 디자인이 그라디언트·커스텀 레이아웃이라 실제 CSS를 그대로 렌더해야 함. satori(HTML→SVG)는 CSS 제약이 커서 이 디자인과 충돌.

### 폰트 (교체 가능)
- 이미지 출력이라 **웹 안전폰트 제약 없음** — 아무 `.ttf/.otf`나 사용 가능.
- `knowledge/cards/fonts/`에 폰트 파일 배치 + 설정에서 **3종 지정**: 헤드라인 / 코드(모노) / 한글 본문.
- 템플릿은 `@font-face`로 로드 → Puppeteer가 이미지에 구워 넣음.
- **구체 폰트는 빌드 시 결정**: 후보 조합 몇 개를 실제 렌더해 비교 후 사용자가 선택. (v1은 전역 설정 1벌, 카드별 오버라이드는 YAGNI)

### HTML 카드 템플릿 — 디자인 스펙 (방향 C · 볼드 네온)
확정된 시각 언어:
- **배경**: 딥퍼플 그라디언트 `linear-gradient(160deg,#1d1440,#150e30)`.
- **강조(네온)**: 라임 `#c2f542` (카드별 `accent`로 교체 가능하게 설계).
- **타이포**: 헤드라인 = 큰 볼드 산세리프 / 코드 = 모노스페이스 / 본문 = 산세리프.
- **질문 카드**: 배지(`도메인 · 개념`) → 코드 패널(전체 코드 가독성 필수, 네온 토큰 하이라이트) → 큰 헤드라인("출력은? 🔥") → "정답은 댓글에서" + `@handle`.
- **정답 카드**: 배지("정답") → 큰 네온 정답값(`1 2 1`) → 짧은 "왜"(2줄) → **마무리 = 박스 없는 볼드 문장**(키워드를 네온색으로: "배낭은 **함수**가 아니라 **호출**이 갖는다") → `@handle`.
- **금지(AI 클리셰 회피)**: 좌측 보더 콜아웃 박스 ❌, 장식용 이모지(💡 등) ❌.

## 5. `/card` 스킬 (`.claude/skills/card/`)

사용자가 명시적으로 발동. 세션 자동 제안 아님.

### 모드
- **`/card <개념>`** (개념 지정) → 그 개념으로 카드 제작.
- **`/card`** (인자 없음) → 카드 **후보 몇 개 추천** → 사용자가 선택.

### 자격 (eligibility)
- 기본 자격 = **`feynman_passed: true`** (확실히 학습된 개념만 발행 대상).
- **추천 모드**: `feynman_passed: true` **AND** `mastery ≥ 4` 인 개념만 후보로 올림. (이미 카드로 만든 것은 후순위/제외)
- **사용자 지정 모드**: 사용자가 직접 이름을 대면, 자격 미달이어도(예: 회귀로 `mastery: 3`) **경고만** 하고 결정은 사용자에게. ("이거 지금 m3 회귀 상태인데 낼래?")

### 제작 흐름
1. `/card` 발동 → (지정 or 추천으로) 개념 확정.
2. 코치가 해당 개념 페이지의 **앵커에서 간결한 Q+A 초안**을 뽑아 제안(질문코드·헤드라인·정답·왜·한줄정리·캡션).
3. 사용자가 다듬어 **승인** → `knowledge/cards/<id>.md` 저장(`status: approved`).
4. 렌더 스크립트로 PNG 2장 생성 → 사용자가 스레드에 **수동 업로드**.
5. 발행 후 `status: published` + `published` 날짜 기록, `publish-queue.md` 갱신.

## 6. 위키 통합

- **`learning-os/publish-queue.md` 신설** — 카드 파이프라인 추적(`review-queue.md`의 발행판). 상태별(`draft`/`approved`/`published`; **rendered = PNG 존재 여부로 파생**, 별도 status 아님) 카드 목록.
- **`CLAUDE.md` 포인터 한 줄** — "발행 트랙은 `/card` 스킬로 돈다. 자격 = 파인만 통과 개념. 자동 제안 아님(사용자 발동)." 헌법에 존재만 명시, 상세는 스킬이 소유.
- 카드 생성 시 개념 페이지의 `related`/"실전 사례"에 카드 역링크 옵션(가벼운 수준, v1 필수 아님).

## 7. v1 범위 (YAGNI)

**넣음**
- `knowledge/cards/` 소스 포맷 + **샘플 카드 2장**(closure `makeCounter` + 하나 더, 예: event-loop 또는 promise).
- HTML 카드 템플릿(방향 C, 교체형 폰트/accent).
- `scripts/render-cards.js` (approved 카드 → PNG 2장).
- `/card` 스킬(양 모드 + 자격 로직).
- `learning-os/publish-queue.md` + `CLAUDE.md` 포인터.

**안 넣음 (나중)**
- 스레드 API 자동 포스팅 → 수동 업로드.
- 페이지 프로즈 자동 추출 → 코치 큐레이션.
- Q/A 넘는 다장 캐러셀, 카드별 폰트 오버라이드.
- 쇼츠(영상) 렌더 — 콘텐츠 원자는 호환되게 두되 파이프라인은 미구현.

## 8. 성공 기준
- `/card 클로저` (또는 `/card` → 추천에서 선택) 한 번으로 → Q+A 초안 제안 → 승인 → `knowledge/cards/`에 카드 저장.
- `render-cards.js` 실행 시 approved 카드가 **1080×1350 PNG 2장**(질문·정답, 방향 C 디자인)으로 나옴.
- 나온 PNG를 사람이 스레드에 그대로 올릴 수 있는 품질(코드 가독성, 브랜드 일관).
- 폰트/accent를 설정에서 바꾸면 카드에 반영됨.

## 9. 나중에 정할 디테일 (구현 계획/빌드 시)
- 구체 폰트 3종(후보 렌더 비교 후 선택).
- `id` 네이밍 규칙(`<concept>-<anchor>-NN`).
- 코드 신택스 하이라이팅 방법(간단 토큰 규칙 vs 라이브러리).
- `site/cards/dist/` 커밋 여부(산출물 버전관리 vs gitignore).
- 두 번째 샘플 카드로 쓸 개념 선정.
